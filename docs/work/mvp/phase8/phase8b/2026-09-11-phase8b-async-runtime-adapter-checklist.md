branches. The blocking one was a false measurement recorded as fact: the plan's Task 7 Step 8 mutation

design's addendum, the roadmap's bullet and status note and a test comment all said the opposite; they

event emitted and every other outstanding delay stranded, and the bounded workers join `P8-75` rests
on was pinned by nothing; both are repaired on the code and tests branches and recorded as **`P8-76`**
and guards 30–32. The nits — two run counts, `P8-75`'s unreachable `Data#==` rationale, three

a close from inside a task that burned the whole budget — are fixed where they sit, the last one in

**Review round 1, repaired 2026-09-21.** One should-fix and two nits, every one closed on the branch
that owns its file. The should-fix was a validation hole in `#delay` (R1-1): a `NaN` duration is a
`Numeric` that answers false to both `negative?` and `zero?`, so the design's two checks let it reach
the timer, whose deadline-ordered list it poisoned — the timer thread reported one diagnostic and
exited for good, the future never settled, and every later `#delay` on that pool raised a bare
`ArgumentError` synchronously from the sort (4.0.6 and 3.2.11); a `Complex`, a `Numeric` with no
`#negative?`, was a bare `NoMethodError`. `validate_duration!` now asks `real?` and `finite?` beside
the two checks, so `NaN`, either infinity and a `Complex` raise `Dexpace::InvalidArgumentError` before
anything is scheduled (**`P8-77`**, guard 33); the same shape guarded `shutdown_timeout`, where a `NaN`
budget made `#release` raise a bare `ArgumentError` out of `#close` with the latch already flipped, so
`.build`'s helper became `finite_non_negative!` (guard 34). The nits: the `ASYNC-2` row's misquoted
test name (R1-2) reads as written, and the design's teardown-order assertion — group 4 of its testing
strategy, which the diagnostics suite did not carry (R1-3) — is now the last statement of that suite's
`teardown`, red when neither a test's own cleanup nor the restore reaches a key (guard 35). Core's
`Async.validate_delay` and `Clock::Guard.duration` share the hole and are phase 10's (Findings routed).
Nothing in this paragraph moves a requirement row's mark.

**Review round 2, repaired 2026-09-21.** One blocking finding and two nits, every one closed on the
branch that owns its file. The blocking one (R2-1) was the design's own finding 1 arriving at the gem's
own door: the timer thread behind `#delay` is the gem's **second** `::Thread.new` carrier, spawned by
the first positive delay from *that caller's* fiber, and it inherited that caller's storage at creation
and was given neither of `P8-20`'s clears and no per-delay snapshot — so every later delay's
`#on_settle` and `#then` callback ran under the first caller's context, a contextless caller's handler
read the first caller's trace id, and a key one handler wrote was visible to every later one (measured
on 4.0.6 and 3.2.11; `ASYNC-8` names callbacks explicitly, and the `ASYNC-8`/`ASYNC-10`/`ASYNC-12` rows
stated no exclusion). `Timer#schedule` now captures `Diagnostics.capture` per entry on the scheduling
caller's thread, the `Entry` carries it, the timer thread clears its inherited storage at start and
again after every fired callback, which runs under `Diagnostics.with` over the entry's snapshot, and
the shutdown callback runs on whichever thread stopped the timer under the same install-and-restore
with that thread's own context put back (**`P8-78`**, extending `P8-20` to the second carrier; guards
36–40). The diagnostics suite gains five timer cases in a nested class beside the worker ones and every
queue pop in it is bounded (R2-3); the composed suite's one reason-less `rubocop:disable` is gone
(R2-2). The `ASYNC-8`, `ASYNC-9`, `ASYNC-10` and `ASYNC-12` rows below now state the timer half; no
row's mark moves.

## Matrix facts, re-run on every interpreter

The design's twenty facts and the plan's nine were re-run on 2026-09-21 on 3.2.11, 3.3.12, 3.4.10 and
4.0.6 — the pool-specific ones as `thread/matrix_facts_test.rb` (12 runs green on each), the Fiber

deliberately not duplicated. Identical on every row: the three full-queue behaviours of `SizedQueue`
(`push(x, true)` raises `ThreadError: queue full`, `push(x, timeout:)` answers nil, `<<` blocks);
`close` drains queued items then answers nil and a push on a closed queue raises `ClosedQueueError`, a
`StandardError` that is not a `ThreadError`; `Queue#pop` answers nil for a timeout, a closed queue and
a pushed nil alike (the reason the drain carries a non-nil sentinel and re-reads the clock);
`pop(timeout: nil)` blocks indefinitely and wakes on close; `SizedQueue.new(0)` and `.new(-1)` refuse;
`Proc.new` with no block raises; a frozen `Data` crosses a thread with its `Proc` intact; a thread that
rescues `::Exception` swallows `SystemExit`, `NoMemoryError`, `Interrupt` and `NotImplementedError` and
lives; a thread named inside its body reads back from `Thread.list`; a worker sees `Fiber.scheduler`
as nil whatever the caller's thread installed; `Thread.report_on_exception` defaults to true. **What
differs, and where it is recorded**: `Fiber[:k] = nil` deletes the key on 3.3+ and retains it with a nil
value on 3.2.11 (core's pin; `P8-74`), which is why every worker-side read in the diagnostics suite goes
through `Diagnostics.capture` and the ensure-clear proof writes a never-held key; `Fiber.set_scheduler`
warns "Scheduler should implement #fiber_interrupt" on 4.0.6 alone, so the copied scheduler defines it;
`Hash#inspect` and a `NoMethodError`'s wording differ between the floor and 4.0.6 (the as-built page
says so); and one connection in the composed suite starts net-http 0.4.1's process-wide Timeout thread
on the 3.2 row and nothing on 4.0.6 (P8-62 — the composed file requires the shared warm-up itself).
