## Conflicts
- **RuboCop baseline: the design wins — `rubocop` + `rubocop-minitest` + `rubocop-performance` at `--fail-level=convention`, and `rubocop-airbnb` is not inherited.** Resolves `tooling-and-quality-gates/86d763f1`. This is not a preference: the styleguide's incantation does not run. Verified on 2026-09-05 against `rubocop-airbnb` 8.1.0 (released 2025-12-19) and `rubocop` 1.90.0 — (1) the styleguide's literal `inherit_gem: rubocop-airbnb: .rubocop.yml` fails, because the gem ships no `.rubocop.yml`; its config is `config/default.yml`. (2) `inherit_gem` alone fails with seventeen `unrecognized cop or department Airbnb/…` errors, because 8.0.0 moved the custom cops to RuboCop's plugin system, so the gem must be loaded through `plugins:` instead. (3) With the plugin loaded, `rubocop` refuses to start at all against the resolved `rubocop-capybara` 2.23.0 — `Capybara/CurrentPathExpectation` has moved and the gem's own config is stale — so a `rubocop-capybara ~> 2.22.0` pin is required to run, and obsolete-parameter warnings from `config/rubocop-lint.yml` remain. (4) The baseline it delivers is weaker, not stronger: `AllCops: DisabledByDefault: true` leaves 236 of 1016 cops enabled against 435 of 720 for the design's set, every `Minitest/*` cop off in a Minitest-only repository, and `Style/StringLiterals` disabled although the styleguide's own deviation ledger mandates double quotes. (5) It sets `Rails: Enabled: true` and drags `rubocop-rails`, `rubocop-rspec`, `rubocop-capybara`, `rubocop-factory_bot` and transitively `activesupport` and `rack` into the dev bundle — 36 gems against 18 — and fires `Airbnb/ModuleMethodInWrongFile`, a Rails-autoloading cop, on a plain gem file. What the SDK does instead: `plugins: [rubocop-minitest, rubocop-performance]`, `NewCops: enable`, `TargetRubyVersion: 3.2`, `--fail-level=convention` with waivers only as scoped inline directives carrying a reason (`NFR-7`), plus the custom SPDX-header cop (`NFR-13`) and the lint rules that forbid `Time.parse`, `URI::DEFAULT_PARSER` and a locale symbol on `downcase`/`upcase`/`casecmp`. Every cop setting the styleguide names by hand is transcribed into `.rubocop.yml` directly — double quotes, 2-space indent, 100 columns, trailing commas, the 25-line method cap and the metric caps — so the styleguide's *rules* are enforced even though its *distribution mechanism* is not used. On pre-commit `--autocorrect-all`: `-A` applies safe **and unsafe** autocorrections (the styleguide's rationale says "all safe autocorrections", which is not what the flag does), and an unsafe autocorrection that silently changes semantics in a correctness-critical HTTP client is exactly the risk `NFR-7` exists to surface; this repository runs `rubocop --autocorrect` (safe only) as a developer convenience and `rubocop --fail-level=convention` with no autocorrection as the gate. The styleguide-amendment alternative (fixing the broken `inherit_gem` example and scoping `rubocop-airbnb` to applications) was considered and not taken; this is recorded as an SDK deviation instead.

- **Lockfile discipline: the SDK does not commit `Gemfile.lock`, and CI does not run `bundle install --frozen`.** Resolves `tooling-and-quality-gates/f37d7536` and `tooling-and-quality-gates/e00c3fc5`. Library-versus-application once more, and this time the deciding fact is the matrix itself. A lockfile is a resolution against one interpreter, and this repository's supported range is 3.2 through 4.0, where the default-gem set genuinely differs: verified on 2026-09-05 against real interpreters, Ruby 3.2.11 has 71 default gems and an undefined `Gem::BUNDLED_GEMS::SINCE`, Ruby 3.4.10 has 58 default gems and 28 bundled, and Ruby 4.0.6 has 46 default gems and 23 bundled — twenty-six names are default on 3.2 and are not default gems on 4.0 (`base64`, `logger`, `ostruct`, `benchmark`, `fiddle`, `pstore`, `bigdecimal`, `csv`, `drb`, `irb`, `rdoc`, `reline`, `set`, `pathname`, `cgi` and eleven more). A single committed lockfile cannot be `--frozen`-installed across those rows without either pinning the development toolchain to the intersection or failing a row for a reason that has nothing to do with the change under test, and the styleguide's rule was written for an application whose deploy target is one interpreter. Consumers never see this repository's lockfile in any case: a gem ships a gemspec, and Bundler resolves the consumer's own graph. What the SDK does instead: `Gemfile.lock` is listed in `.gitignore`, every matrix row runs a plain `bundle install` and therefore resolves against the interpreter it is actually testing, and `bundler-audit check --update` runs against that fresh resolve — which makes the CVE gate report the versions CI just installed rather than a snapshot taken on one laptop, and is what enforces `docs/sdk-design-ruby/03-seam-by-seam-idiomatic-mapping.md` §3.4's `json >= 2.19.9` floor over time. What is lost and is not replaced: byte-identical dependency versions between two developers on the same Ruby, and the drift signal `--frozen` gives on an unreviewed `bundle update`. The mitigation is that every gate that could be perturbed by a dependency bump — RuboCop, Steep, `rbs validate`, SimpleCov, YARD — is blocking on every row, so a bump that changes a gate's verdict fails the build rather than passing quietly. The styleguide-amendment alternative (scoping rule 1.1's lockfile clause to applications and to projects testing on a single interpreter) was considered and not taken; this is recorded as an SDK deviation instead.

## Superseded
- **The SPDX header gate is a RuboCop cop, so it covers `lib/` and `test/` and cannot reach `sig/**/*.rbs`, which ships inside every gem.** Supersedes `tooling-and-quality-gates/3085561e` ("An SPDX license header is required per file, checked by a custom RuboCop cop") on the word *per file*. The rule's mechanism is right and its scope is narrower than its wording: RuboCop inspects Ruby source, `.rbs` is not Ruby source, and no cop parses it. `NFR-13`'s own conformance clause is "scan **all source files** for the required header", and `CLAUDE.md` states that `sig/` "mirrors `lib/` one file per file and **ships inside each gem**, so a consumer's `steep check` sees it" — so the signatures are shipped source with no header and no gate. Checked on 2026-09-12: every `` ```rbs `` fence in `docs/work/mvp/phase0/2026-09-05-phase0-scaffold-and-quality-gates.md` opens with `module Dexpace`, carrying no header, and by phase 8 roughly as many `.rbs` files ship as `.rb` files. RBS supports `#` comments, so the header is expressible; what is absent is a check. This is `## Superseded` rather than `## Conflicts` because the two documents do not disagree — the harvested rule is phase 0's own design, restated accurately, and what moved is the observation that the mechanism it names cannot cover the file set the requirement names. Recorded as `OI-50`, whose two resolutions are a small Rake gate over `sig/**/*.rbs` beside the cop, or a deliberate and stated decision that `NFR-13` covers `lib/` only. Phase 9 dispositions `NFR-13` with the gap named rather than closing it, because phase 9 reports and phase 10 repairs (`P9-6`).
