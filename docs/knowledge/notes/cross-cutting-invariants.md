## Reference
- **`XCUT-11`'s audit predicate, and why *frozen with no instance variables* is the wrong one.** **The harvested rule cross-cutting-invariants/89eb6533 stands unchanged and is NOT overridden** — its key is deliberately left unbackticked here, because backticking it is what makes every query result print `[overridden by notes/…]` beside it, and a correct rule should not read as overridden. What this note adds is the *audit consequence* the rule implies and does not state. That rule fixes the latch shape this port uses — "close idempotence is implemented as a latch, a `@closed` boolean flipped under a `Thread::Mutex`, held only across the flip and released before `#release` runs … because Ruby's Mutex is per-fiber-owned and non-reentrant" — and extends it with the consequence that rule has for the *audit* rather than for the implementation. `XCUT-11` requires that "per-call mutable state MUST live on the call's stack/local state, not the shared instance, and any shared mutable state MUST be synchronized", and nine hand-forward rows across five phase documents name nine different objects as "the audited shared instance" without any phase defining what audited means. The obvious predicate — frozen, and `instance_variables` empty — condemns every `Dexpace::Closeable` in the SDK, because the latch this very rule prescribes *is* mutable state on a shared instance. So phase 9 fixes the predicate as: **frozen with no instance variables, or every instance variable declared by the subject as one of two named kinds — a `Thread::Mutex` together with the state that mutex guards, or `Closeable`'s `@closed` latch** — with the declaration supplied per object, because only the object knows which ivar is its mutex and which is the state under it. The behavioural half is two shapes rather than one: the sixteen-thread race `XCUT-11`'s own conformance clause names, and the **two-fibers-on-one-thread** shape phase 8b handed forward as "the only shape that proves a per-fiber mutex is not held across a suspension point", which a thread-only test cannot see for the reason this harvested entry gives. Verified on 3.2.11, 3.4.10 and 4.0.6: `instance_variables` on a frozen instance holding one mutex returns `[:@lock]` identically, and a `Data.define` subclass is frozen on construction on all three. `Dexpace::Conformance::SharedInstance.audit(object, mutable:, ids:)` is the predicate.

- **The repository-wide invariant scans are Rake gates over `RubyVM::AbstractSyntaxTree`, not conformance assertions, and a `:CALL`-only scan is wrong.** Relates to cross-cutting-invariants/7e6a9aea (`XCUT-14`'s hard cap and drain-to-cap loop) and, by the same argument, to `XCUT-9`'s single-walk rule and `SEAM-2`'s no-concrete-seam rule — **neither key is backticked, because neither harvested rule is false**; what is added is how each is checked. Four checks handed forward to phase 9 are statements about the **absence of a second implementation** rather than about what one implementation does — `XCUT-9`'s "nothing else walks `#cause`", `XCUT-14`'s "one bounded-map implementation", `SEAM-2`'s negative test over core's tree, and `SSE-37`'s `gates:serde_boundary` `PENDING` list — and none can be a portable conformance assertion, because a scan of `gems/*/lib/` is meaningless in a consumer's process where `gems/` does not exist. They land as Rake gates. The mechanism is `RubyVM::AbstractSyntaxTree` rather than a regex, because `grep '\.cause'` matches a comment, a string, an `# XCUT-9` citation in a test header and the requirement ID itself. Verified on 2026-09-12 on 3.2.11, 3.4.10 and 4.0.6: the module is present on all three, `parse_file` returns a `SCOPE` node on all three, and parsing emits **no warning** under `-w` — which is load-bearing, because phase 0's shared test case overrides `Warning.warn` to raise, so a scanner that warned would fail the suite that runs it. `prism` is absent on the 3.2 floor (`LoadError`) and present at 1.9.0 on 3.4.10 and 1.8.1 on 4.0.6, so the AST route needs no conditional require where Prism would. **Four measured corrections to the obvious implementation, each one a gate that reported clean over a live defect.** (1) A send is **three** node types, not one — `a.cause` is `:CALL`, `b&.cause` is `:QCALL`, a bare `cause` is `:VCALL`, identically on all three — and a `:CALL`-only scanner returned two hits for a fixture containing three `#cause` sends. (2) A **reflective** send bypasses call-syntax scanning entirely: `send(:cause)`, `__send__`, `public_send` and `method(:cause)` took the catch rate from 3 of 7 realistic shapes to 6 of 7, the seventh — `send(variable)` — being statically undecidable. (3) **A Symbol literal is a `:LIT` node on Ruby 3.2.11 and a `:SYM` node on 3.4.10 and 4.0.6**, which is the reverse of the usual direction and is why the reflective scan must name both: naming one gave 6 of 7 on the floor and 2 of 7 on the newer rows, a gate strictest exactly where it runs least (`OI-52`). (4) `Hash` is `:CONST` and `::Hash` is `:COLON3`, so `@h = ::Hash.new` escaped a check naming only the first. **And one clause moved rather than being fixed:** `XCUT-14`'s drain-loop clause is not decidable behaviourally — a check-then-evict map was indistinguishable from a drain loop in 0 of 30 runs on 3.4.10 and 4.0.6 at 16 threads and 0 of 20 at 64 threads by 5000 inserts, because the GVL serialises the interleaving the clause is about — so it is checked as **shape**, asserting the eviction sits inside a `while`/`until`, which is deterministic on all three. A gate that reports clean while the invariant is broken is worse than no gate, which is why phase 0's failing-fixture discipline applies to these five as much as to its own seventeen.
