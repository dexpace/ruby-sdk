## Superseded
- **The rule is right and the obvious spelling of it forwards the credential: `URI::Generic#userinfo = nil` is a silent no-op, and `REDIR-12` needs `#userinfo = ""`.** Answers `redirect-handling/b42d265d` ("Userinfo in the Location target (user:pass@) must be dropped before re-issue, and server-supplied embedded credentials must never be used"), which states the obligation without stating the spelling that discharges it — and the spelling that *reads* as discharging it does not. Measured on 3.4.10 for `docs/work/mvp/phase6/phase6b/2026-09-09-phase6b-redirect-design.md`: parsing `https://user:pass@ex.com/p?q=1`, assigning `userinfo = nil` and rendering gives back `"https://user:pass@ex.com/p?q=1"` — unchanged, the credential survives — while `userinfo = ""` gives `"https://ex.com/p?q=1"` with `#user` `nil` and the `@` gone. Confirmed at source in `uri/generic.rb`: the writer opens `if userinfo.nil? then return nil`, before `check_userinfo` and `set_userinfo` are ever reached, so assigning `nil` is observably a no-op rather than a clear. `set_userinfo` is additionally **protected**, so a third obvious route needs a `send`. **Why this is a `## Superseded` entry and not a footnote:** `REDIR-12` says server-supplied embedded credentials MUST never be used, and the failure mode is silent — the strip appears to happen, every structural test of "the step calls the strip" passes, and the credential goes out on the wire to the redirect target, which is by construction an origin the caller did not choose. It reopens on the other channel exactly the leak `REDIR-7` and `REDIR-11` exist to close. **What it licenses:** `Location.resolve`'s result has `#userinfo = ""` called on it unconditionally before the resolved URI is used for anything — comparison, logging, or the follow-up request. **What it does not license:** trusting `#user = nil` alone to clear `#password` too; that was not measured, because `#userinfo = ""` is sufficient and is the one call site phase 6b ships. **How to assert it:** on the rendered URL string (`Dexpace::URL.external_form`), never on `#userinfo` being `nil` — a resolved-but-not-yet-stripped URI can report `#userinfo` as `nil` for the unrelated reason that the input carried none, which makes a `#userinfo.nil?` assertion pass for the wrong reason on that input. **Floor-straddling and not yet closed:** `URI::Generic`'s setter bodies have not been diffed across 3.2.11 / 3.4.10 / 4.0.6; phase 6b's plan re-runs the measurement on the full matrix as its first task before relying on the fact. See also `../notes/url-and-query-encoding.md`, whose `SEAM-27` entry fixes the sanctioned parser spelling this step resolves with.
