## Superseded
- **Only the BOM-consumed flag persists across `Reader#next_event` calls; the last event id and the current retry value do not.** Supersedes `sse-streaming/2dba42b0` ("The convenience view reuses one reader instance so per-stream state (consumed BOM, current retry value, last event id) is preserved across pulls"), harvested verbatim from design §7.2's parenthesis at `docs/sdk-design-ruby/07-pagination-sse-and-serialization.md:79-84`. `SSE-16` is a MUST — "**only** the 'BOM already consumed' flag persists across calls; the last-event-id is NOT carried forward" — and `SSE-38` is a MUST that the subsystem "MUST NOT persist a last-event-id across events"; carrying a "current retry value" across events is forbidden by the same "only". `SSE-40`'s own canonical text says "per-stream state (**e.g. BOM consumption**)" and names nothing else. The view does reuse one reader instance, which is `SSE-40`'s actual clause; what that preserves is the BOM flag. Built that way on 2026-09-20: `Dexpace::SSE::Reader` resets all five accumulators — id, event, data, comment and retry — at every dispatch, and `gems/dexpace-core/test/dexpace/sse/reader_test.rb`'s `DispatchTest` asserts the two prohibitions directly ("nothing but the BOM flag persists across calls -- no carried retry value"; "no last-event-id is carried forward") beside the one persistence ("the BOM flag DOES persist").

- **The SSE line machine is built over `Dexpace::IO::BufferedSource#getbyte`, not over phase 3a's `#read_line_utf8`, because `IO-14` and `SSE-2` disagree about a lone CR.** Corrects `sse-streaming/8c25db7d` and `sse-streaming/e98a0668` insofar as either reads as "the SSE machine sits on the hand-written line primitive": the reason both give is right — the primitive was hand-written rather than delegated to `IO#gets` because `SSE-2` wants LF, CR and CRLF all recognised — but what phase 3a hand-wrote follows `IO-14`'s grammar ("a lone `'\r'` not followed by `'\n'` MUST be kept as part of the line's content"; `gems/dexpace-core/lib/dexpace/io/typed_reads.rb`, `read_line_utf8("a\rb\n")` is `"a\rb"` on every supported Ruby), and `SSE-2` requires that CR to terminate a line by itself. Post-processing a `#read_line_utf8` result cannot rescue it either: a conforming CR-only stream contains no `\n`, so the method would buffer the whole stream before returning anything — the read-ahead `SSE-39` forbids and the unbounded allocation the line cap exists to prevent. Built as `Dexpace::SSE::LineReader` (phase 7b, P7-20), which recognises the three terminators natively with a one-byte pushback; `#read_line_utf8` ends v1 with no in-repository caller, and its YARD now says so.

- **`Enumerator#next` on a fiber that died by exception starts `#each` over.** Adds to `sse-streaming/4d83311b` (`SSE-29`) and to `io-and-byte-streams`' `.over` rule: after a `Dexpace::IO::BufferedSource.over(chunked)` has raised a mid-stream failure out of `#getbyte`, the NEXT `#getbyte` does not answer `nil` and does not raise a second time — the enumerator's fiber is dead, `Enumerator#next` creates a fresh one, and the body's `#each` runs again from its first chunk, so the pull re-delivers the stream's first byte. Measured on 2026-09-20 on 3.2.11, 3.3.12, 3.4.10 and 4.0.6 (`gems/dexpace-core/test/dexpace/sse/matrix_facts_test.rb`, "after a mid-stream failure BufferedSource.over's enumerator RESTARTS instead of ending"). The SSE facade never meets it because `SSE-27`'s `closed?` check runs before every pull and the facade closed itself on the failure; a bare `Reader` driven again after a raise would. Phase 3a's residue, routed to phase 10's inbound list by phase 7b's checklist.
