## Conflicts
- **`# typed: strict` applies nowhere in this repository, test files included, and `srb tc` is not a suite here.** Resolves `testing/de6fe7e3` and `testing/79254878`. Both rules are conditional on Sorbet, and `../notes/type-system.md` records why this port has none: `sorbet-runtime` would be an `add_dependency` line in `dexpace-core.gemspec`, which `SEAM-1`/`NFR-1` forbid and the gemspec audit mechanically rejects. Those two rules are restated here rather than left to be inferred from the `type-system` note, because a reader auditing the Minitest group by chapter or topic never reaches that note, and a `# typed:` sigil written into a test file on the strength of this chapter would be the one file the type-system note did not name. What the SDK does instead: no file in `lib/`, `test/`, `sig/` or `.rubocop/` carries a `# typed:` sigil; the `Sorbet/*` cops are not in the cop set; and the first suite CI runs, in `srb tc`'s place, is `rbs validate` followed by `steep check`, which are blocking and precede Minitest in the default Rake task exactly as the styleguide's ordering argument asks. The type discipline the rule wanted for test code is kept where RBS can express it: `sig/` mirrors `lib/` one file per file and ships inside each gem, and a test tree is added to the `Steepfile` as its own named target when its helpers become production-quality code worth checking — never as a blanket relaxation, and never by sigil. The styleguide-amendment alternative (making chapter 11's typing rules conditional on the project using Sorbet at all) was considered and not taken; this is recorded as an SDK deviation instead.

## Superseded
- **Minitest 6.0.0 ships no `minitest/mock.rb`, so `Minitest::Mock` and `Object#stub` do not exist on Ruby 4.0.6 — the top row of this repository's CI matrix.** Supersedes `testing/e27df4c7` ("Reserve true test doubles (stubs, `Minitest::Mock`) for genuine externals…") and `testing/70473c9d` ("use a scoped `Time.stub :now, fixed_time do ... end` only when the caller cannot be refactored") for that row, and with it the reachability of every `.stub`-based double in this repository. Measured on 2026-09-12 against all three installed interpreters: `minitest 5.25.1` on **3.2.11**, `5.25.4` on **3.4.10**, **`6.0.0` on 4.0.6**, with `Gem::Specification.find_by_name("minitest").default_gem?` `false` on every one — Minitest is a **bundled** gem across the whole range, which is `OI-43` confirmed beyond the single interpreter it was measured on. The new fact: on 5.25.x the gem ships `minitest/mock.rb`; on 6.0.0 it does not, `require "minitest/mock"` raises `LoadError`, and the gem's `lib/` listing has lost both `minitest/mock.rb` and `minitest/unit.rb` while `assertions.rb`, `test.rb`, `autorun.rb`, `spec.rb` and `benchmark.rb` remain. Every assertion name this repository uses survives: 22 were checked, from `assert_equal` to `assert_in_delta`, and all 22 are still defined on `Minitest::Assertions` under 6.0.0. This is `## Superseded` rather than `## Conflicts` because it is not two documents disagreeing — it is one fact about a real interpreter in the supported range, and a test written on the strength of the harvested rule would not load there. Why it matters beyond style: phase 8a's plan calls `Dexpace::Conformance::TransportSuite.stub(:assertions, …)` in two fences, and a suite that cannot load makes the 4.0 row **red** — not advisory, so this is not an `NFR-17` gap: it falsifies `docs/first-release.md`'s range blocker, "the `dexpace-conformance` suite passing across the full supported Ruby range, 3.2 through 4.0". (An earlier form of this entry inferred that an unloadable suite made the row advisory, which `NFR-17` forbids; that inference is struck.) What this repository does instead: a test that needs to observe a call records it on a hand-written fake named `FakeX` (`testing/630ba094`, `testing/7ecef8e8`), a test that needs the clock injects it (`CFG-15`'s `Clock` seam, which exists for exactly this), and a test that needs to intercept `Warning.warn` installs and restores it in an `ensure` rather than reaching for `stub`. The open question the note does not settle, because it belongs to the root `Gemfile` and not to a test file, is recorded as `OI-49`: whether the `minitest` entry is pinned `~> 5.25` — keeping `stub` available and leaving the 4.0 row running a Minitest its interpreter does not ship — or left unconstrained, making the 4.0 row a different framework major from the other three.
